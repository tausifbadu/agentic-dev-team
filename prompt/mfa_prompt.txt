Build a Multi Time Frame Analysis web app for Indian NSE stocks using a free data source.

Preferred free data source:
Use yfinance as the default source for Indian stock historical data.
Assume Indian NSE symbols use the .NS suffix, for example:
- RELIANCE.NS
- TCS.NS
- INFY.NS
- HDFCBANK.NS

Business Goal:
A user enters or selects an Indian NSE stock symbol and sees Multi Time Frame Analysis for:
- daily
- monthly
- yearly

Definition of MFA for this project:
For each timeframe, the backend should calculate and return a normalized analysis that the frontend can render consistently.

For each timeframe include at least:
- timeframe name
- current close price
- comparison baseline or previous close
- percent change
- trend direction (bullish, bearish, neutral)
- high
- low
- any summary label or insight needed for the UI

Backend Responsibilities:
- Build a FastAPI backend API for a given Indian stock symbol.
- Expose an endpoint such as:
  GET /mfa?symbol=RELIANCE.NS
- Fetch historical OHLCV stock data using yfinance.
- Support Indian NSE stock symbols with the .NS suffix.
- Calculate normalized MFA output for daily, monthly, and yearly timeframes.
- Return a stable JSON response contract that frontend can render directly.
- Handle invalid stock symbols.
- Handle missing or empty historical datasets.
- Handle source/data-fetch failures gracefully.
- Return clear error responses with useful messages.
- Use Pydantic models for request and response schemas.
- Add tests for API responses and calculation logic.
- Mock external data calls in tests. No real network calls in tests.

Frontend Responsibilities:
- Build a React frontend page for localhost use.
- Provide an input box or dropdown for stock symbol selection.
- Call the backend MFA API and display daily, monthly, and yearly analysis.
- Show a chart to visualize the three timeframes.
- Show summary values in a readable UI, such as cards or a compact table.
- Support loading state while fetching data.
- Support error state when backend/data fetch fails.
- Support empty state when no data is available.
- Keep the UI simple, readable, and easy to run locally.
- Use HTML/CSS and React components with basic styling.

Chart Requirements:
- Show a visual comparison of daily, monthly, and yearly analysis for the selected stock.
- Prefer a simple and reliable React charting library.
- If a chart library is needed, choose one that is lightweight and straightforward to integrate.
- The chart should consume the backend's normalized MFA response and not force frontend to calculate financial metrics.

Important Edge Cases:
- invalid stock symbol
- unsupported symbol format
- no historical data returned
- yfinance/source failure
- partial or null values in returned data
- chart rendering when one timeframe is missing
- backend returns error response
- frontend receives empty response
- tests must mock external data access
